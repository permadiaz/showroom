# Phase 6C — Follow the Thread

## Scope
Workspace's primary Show now follows request CM-27 through scheduling, discussion, a meeting-end pause, a project Space and inline thread, one shared working document, contextual assistance, and a reply. The optional fragmented-workday comparison returns to the same new connected journey. Cloud, Migration and Ask Your Data source modules, styles and content are unchanged. Global shell design is unchanged; app hooks only support Workspace's persistent request and keyboard entry.

## Implemented
- A retained request DOM node, stable subject, people and context identity. Finite position movement only; no autoplay or new animation loop.
- Calendar's existing time/people/link/attachment gates, including external availability and separate file-access caveats.
- Four presenter-controlled discussion contributions before notes. Two manual meeting-end reveal beats.
- Inline replies remain beside the parent Space on desktop, below it on mobile. Closing the completed thread preserves one unresolved downtime topic.
- Three contributions to one working assessment document. Unknown data volume and workload owner remain unknown.
- Gemini summary requires the preceding context and retains open questions. Reply is explicitly a simulated unsent draft.
- Continuous work-thread final instead of an application grid on the primary journey. Two manual reveals before optional discovery.
- Six discovery choices create explicit local workspace_continuity signals. No inference, persistent storage, network capture or CRM.
- Compact customer-fit Sell guidance; Tasks added to eleven Learn modules, nine Calendar exercises and five Chat/Space classifications retained.
- Content metadata separates referenced real capabilities, simulated execution and conceptual choreography. All demo product actions are local simulations.

## Responsive implementation and verification limits
CSS adapts at 600px and 1050px, with a bounded viewport stage, scrollable scene content, non-overlapping controls, flexible columns and a continuous vertical final thread on phones. Intended review widths: 360, 390, 430, 1280, 1440, 1920.

Actual browser rendering, tap behavior, screenshots, contrast measurements and animation perception at those widths were NOT verified. The managed environment lacks the supported control-browser capability; Sites instructions require skipping browser QA rather than substituting an unsupported browser path. Automated HTML/state tests are not a substitute for visual acceptance.
